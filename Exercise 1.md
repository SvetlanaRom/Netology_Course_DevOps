Задача 3
1.	100 виртуальных машин на базе Linux и Windows, общие задачи, нет особых требований. Преимущественно Windows based-инфраструктура, требуется реализация программных балансировщиков нагрузки, репликации данных и автоматизированного механизма создания резервных копий.
**Система управления виртуализацией**: Hyper-V
**Причина**: Так как преимущественно будут ВМ с Windows

2.	Требуется наиболее производительное бесплатное open source-решение для виртуализации небольшой (20-30 серверов) инфраструктуры на базе Linux и Windows виртуальных машин.
**Система управления виртуализацией**: KVM
**Причина**: Почитала, что сейчас KVM обеспечивает более высокую производительность и минимальные задержки для ВМ на базе Linux и Windows без дополнительной траты ресурсов, чем Xen

3.	Необходимо бесплатное, максимально совместимое и производительное решение для виртуализации Windows-инфраструктуры.
**Система управления виртуализацией**: Hyper-V
**Причина**: Hyper-V обеспечивает нативную совместимость с гостевыми ОС Windows

4.	Необходимо рабочее окружение для тестирования программного продукта на нескольких дистрибутивах Linux.
**Система управления виртуализацией**: VMWare
**Причина**: VMWare обеспечивает более хорошую совместимость с ОС Linux, чем Hyper-V



Задача 4
Гетерогенная среда виртуализации

К **преимуществам** можно отнести:
1.	Независимость от одного вендора. Если один вендор уйдет с рынка или поднимет цену на лицензию, то есть запасной вариант
2.	Гибкость выбора. Можно выбрать ту систему управления виртуализацией, которая по тем или иным причинам на данный момент и для конкретных задач подходит больше.
3.	При наличии нескольких систем управления виртуализацией можно выполнять плавную миграцию с одной системы управления на другую, если по каким-то причинам одна их них не подошла. Пока выполняется настройка программы в ВМ на одной системе управления, на другой ВМ с этой программой продолжает работать
4.	Можно собрать отказоустойчивый кластер (по крайней мере у VMWare)

К **недостаткам** можно отнести: 
1.	Уровень знания инженеров и их количество. Для качественного обслуживания систем управления виртуализацией нужен определенный набор навыков инженера и у каждой системы свои нюансы, о которых один инженер может не знать.
2.	Сложность мониторинга. Трудно обеспечить единую систему мониторинга для всех систем управления виртуализацией.
3.	Из-за разных форматов дисков сложно мигрировать ВМ с одной системы управления виртуализацией в другую.
4.	Невозможность создания отказоустойчивого кластера с разными средами виртуализации

Если бы у вас был выбор, создавали бы вы гетерогенную среду или нет?
**Ответ**: сложно сказать, я бы смотрела по совокупности требований. По опыту, крайне редко при проектировании создаются гетерогенные среды виртуализации, обычно они возникают в процессе эксплуатации.
